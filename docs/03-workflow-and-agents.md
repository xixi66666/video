# 03 工作流、Agent 与人工拍板

## 1. 执行原则

Agent 负责建议、内容制作和受限工具调用；工作流服务负责依赖、状态、权限、预算、幂等和确认有效性。模型输出不能直接修改这些控制字段。流程引擎执行已发布的工作流定义，不执行模型临时编造的 DAG。

19 种职责见 `specs/agents.json`，按六个工作单元组织。不是 19 个必须同时常驻的进程，也不要求使用不同 LLM。统筹 Agent 只读状态、提出行动计划，通过工具服务提交命令。

## 2. 作用域与实例化

| scope | 实例与复用方式 |
| --- | --- |
| ACCOUNT | N01—N07 按账号档案版本复用；N50 按经营周期执行，不能改写全局历史 |
| IDEA | N08—N14 在灵感和选题对象执行；立项后将批准快照关联项目 |
| PROJECT | 每次视频制作迭代一组实例 |
| SHOT | 每个镜头有独立 scope_key，例如 shot:S004；依赖镜头的成对关系由分镜映射 |
| TRACK | 每条旁白/对白音轨独立；可进一步分段 |
| PLATFORM | 每个“平台 + 账号 + 发布版本”独立实例 |

唯一业务键：`(project_iteration_id, node_definition_version, node_id, scope_key)`；账号/灵感范围的历史版本用 context_binding 关联，不能在复制项目时自动重新调用全部模型。

上游镜头节点进入项目后期节点时是 ALL_REQUIRED 聚合：所有必需镜头已选用，或者有用户确认的删除/替代记录。不能第一个镜头完成就误触发整体导出。两个平台的审阅与发布独立，抖音失败不能误改小红书状态。

## 3. 依赖与可执行条件

`specs/nodes.json` 的 dependsOn 是业务依赖，不是只能串行的队列。N33—N36 可在输入稳定后并行；N38/N39 可并行，N40 等待确定的包装。跨范围复用需要绑定具体产物版本。

自动调度必须同时满足：

1. 节点适用，必需依赖完成或有合法替代；输入版本一致。
2. 路径上的阶段拍板已通过且未过期；节点产物内容状态满足要求。
3. 执行器可用、模型能力验证通过、参数和输入限制符合要求。
4. 预算预留成功，工具调用在授权范围内，未被用户暂停。
5. 没有相同幂等任务已运行；数据库抢占成功。

缺哪项就给出结构化 blocked_reasons，而不是泛化为“生成失败”。与其无关的分支可继续。

同阶段策划允许消费注明 DRAFT 的上游草稿，便于连续生成大纲、脚本与分镜；不因此把草稿标成已采用。哪些草稿可消费由 stage_policy 固定配置。跨越 G03 的正式生产和跨越 G04/G05 的交付不得使用未批准输入。B 不代表每个节点都停一次，只有政策指定的审阅或拍板节点进入 WAITING_REVIEW。

## 4. 三套状态分别管理

### 4.1 节点实例

`NOT_STARTED → READY → RUNNING → WAITING_REVIEW/COMPLETED`。

其他状态：WAITING_INPUT、WAITING_GATE、BLOCKED、FAILED、PAUSED、SKIPPED、CANCELLED、NEEDS_REVALIDATION。SKIPPED 只用于不适用节点，有理由、操作者、替代关系和下游输入校验。未接入不是不适用，必须 BLOCKED 或等待人工结果。

### 4.2 执行尝试 task_attempt

`QUEUED → DISPATCHING → RUNNING → SUCCEEDED / FAILED / CANCELLED / UNKNOWN`。

UNKNOWN 表示远端是否执行或计费未知，先对账，不自动当作 FAILED 重新付费提交。尝试结束不等于素材被采用。节点内的重试产生新 attempt，保留旧记录。

### 4.3 产物版本

生成后 DRAFT，技术检查后 TECH_CHECKED，审阅后 ACCEPTED 或 REJECTED；上游变更可标记 NEEDS_REVALIDATION。SUPERSEDED 只说明已有替代版本，不删除文件。Agent 不能自行把需要人审的产物标记 ACCEPTED。

## 5. 六个拍板节点

| gate | 时机 | 确认对象 | 放行 |
| --- | --- | --- | --- |
| G01 方向 | N07 后 | 目标、受众、定位、栏目、规范的版本组合 | N10 及依赖它的后续选题 |
| G02 立项 | N14 后 | 选题、范围、预算与制作/暂存/放弃决定 | N15/N16 |
| G03 制作方案 | N24 后 | 脚本、声音设定、分镜、预演和难镜样片 | N25—N29 正式批量生产 |
| G04 成片 | N41 后 | 母版、平台封面、标题、配文、声明、检查报告 | N42 |
| G05 发布 | N42 后、N43 前 | 确定平台、账号、发布包哈希、时间和可见范围 | N43 的公开发布动作 |
| G06 周期复盘 | N50 后 | 改进假设、经营周期、下一期投入 | 创建后续迭代或结束 |

G01 可复用有效账号档案确认；G02 是立项界面的主要操作；G03 包含脚本和分镜整体审阅，避免每句脚本弹窗。N25/N27 等现实操作通过手工任务完成，不再额外增加一套阶段审批。

G03 前允许低成本试听、占位图和样片，属于 PREVIEW 子任务，使用独立的小额预览预算；不能以“方案尚未批准”为理由禁止制作方案所需样片，也不能借样片名义批量生产。

确认记录包含 actor、时间、decision、artifact_revision_ids、snapshot_hash、policy_version、target、预算/次数/时间边界、备注。内容或目标变动后重新计算，若与确认快照不同，标记 EXPIRED，并展示具体差异。客户端按钮不能绕过服务端检查。

`after` 指该节点的审阅材料已形成，而非要求拍板相关节点先人为“通过”。N14/N48/N50 的 Agent 可先形成待决定方案，人工的同一次 gate 操作提交选择、完成相关人工节点并创建批准快照，避免“节点等待审批，审批又等待节点完成”的死锁。

G04 可采用一次项目级成片确认加平台包装差异确认，但最终每个平台都生成自己的确定发布包；G05 始终绑定具体平台账号。默认不批量授权未知将来作品。

## 6. 局部返工

1. 编辑生成新的产物版本，不覆盖旧版。
2. 按 artifact_dependency 找到实际引用该版本的下游；不要只按节点编号把整条链清空。
3. 计算影响：无需处理 / 需复查 / 需重做 / 需重新拍板，给出原因和费用估算。
4. 用户选择重做范围，或已授权的模板规则自动处理低成本确定操作。
5. 未受影响镜头和候选素材继续保留；旧成片可播放，但标记“不是当前交付版本”。

例：S004 的一句旁白变化 → 更新该音段 → 对齐与时长复查 → S004 及相邻转场检查 → 受影响字幕与合成更新 → G04/G05 失效。其他镜头不重新生成。仅封面文字变化，不重新配音或制作主体视频。

## 7. 失败、暂停、取消与恢复

- 网络/限流：指数退避、有上限；认证/参数错误：停止并给出配置定位。
- 内容不合格：生成内容问题单，调整条件或方法；不当作网络错误自动无限重试。
- 用户暂停：停止派发新任务；已运行任务继续、申请取消还是等待完成，由工具能力和用户选项决定。
- 取消：本地取消请求不等于远端已取消；记录 CANCEL_REQUESTED，收到证据后更新。
- 进程退出：恢复数据库任务；过期租约先查询外部任务，不盲目重发。
- 轮询与 WebSocket/SSE 断开：状态从持久化任务重建；推送不是唯一真相。

## 8. 无外部连接器时

展示“未接入”，提供制作要求、可导出的提示词/分镜/工作流参数，以及上传结果入口。导入结果记录 MANUAL_IMPORT、真实来源与文件校验。人工输入可使节点继续，但不会增加虚假的 model_usage 或外部执行凭证。

## 9. 下一轮与无限循环控制

N48/N50 只形成 next_iteration_suggestion；用户接受或预授权规则满足后创建新的 iteration_id。单次 DAG 保持无环。每次自动运行限定最大任务数、费用、时长和并发；达到任一限制可恢复地暂停。

## 10. Agent 上下文

只传当前任务所需的已绑定资料、相关历史和明确约束。参考网页、评论和素材元数据是数据，不能提升为系统指令。返回结构化产物及证据，不要求保存隐藏推理过程；记录可审查的行动理由和调用摘要即可。
