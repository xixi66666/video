# 11 异机部署与交接

## 1. 交付物如何使用

当前目录可整体复制到后续开发电脑。文档和规格使用 UTF-8；JSON 为真实可解析的设计样例，但其中模型、文件、地址和哈希都是明确占位，不能直接调用生产服务。

```powershell
Set-Location 'D:\Code\creator-workbench'
python scripts/validate_docs.py
python scripts/render_node_catalog.py --check
```

需要 Python 3 标准库。后续应用尚不存在，当前不能运行 npm dev、Spring Boot 或 ComfyUI；不要把文档校验成功表述为应用启动成功。

## 2. 后续目标机环境登记

| 环境 | 必填信息 |
| --- | --- |
| 控制端 | 系统、Java、Node、数据库、存储、时区、凭据存储方案、备份位置 |
| 模型服务 | 服务商、协议、真实模型 ID、认证引用、网络、能力和价格依据 |
| GPU 执行端 | 系统、GPU/显存、驱动、运行环境、ComfyUI 与节点版本、模型与文件目录 |
| 媒体执行端 | FFmpeg/Remotion 等版本、字体、模板、色彩和输出格式 |
| 平台账号 | 所有者、必要身份状态、真实 API 权限、发布与指标读取方式 |

先验证，再把工具状态由 DOCUMENTED 转为 CONFIGURED/VERIFIED/ENABLED。目标机器硬件不足时可换远端服务，不在本次文档中规定虚构的最低显存。

## 3. 开发与生产隔离

开发使用示例素材、模拟会议数据、测试模型预算和独立输出目录。生产发布需要真实账号和明确 G05。开发模式不能通过一键切换误用生产发布凭据。

## 4. 配置迁移流程

1. 导出模型/模板/节点/Agent/项目配置，不导出密钥。
2. 生成文件 manifest、版本和校验值；备份数据库及原件。
3. 在新机器建立 storage_root 到 storage_key 的映射，不全文替换历史路径。
4. 重新登记 credentialRef，确认模型、执行端地址与网络范围。
5. 验证模型协议、模板依赖与输出；旧验证仅作为历史，不能自动沿用。
6. 对账所有 RUNNING/UNKNOWN 外部任务，决定恢复或人工处理。
7. 试运行一个无发布副作用的示例，验证产物、日志、费用和恢复，再启用生产。

## 5. 备份集合

数据库、原始和采用素材、脚本/分镜/时间线、工作流模板、依赖清单、发布包和授权记录、费用账目。缓存和代理文件可重建。密钥与数据库备份分开管理。

## 6. 交接核对

- 所有 50 节点仍可访问，无本机路径硬编码。
- 模型 ID 与能力映射可编辑，协议适配器状态真实。
- ComfyUI 模板来源、节点 ID 与依赖来自目标机实测。
- 未接入功能明确显示，人工交付可继续。
- G01—G06、预算、版本、影响分析和发布边界按规格执行。
- 测试与生产凭据、素材、账号和目录分别管理。
- 知道哪些东西只是设计、哪些已经实现、哪些已在目标环境验证。
