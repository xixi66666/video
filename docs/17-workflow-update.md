# 17 本轮交互与兼容调整

## 模型选择

顶部“全局模型”是全站入口。角色、作品、节点均有默认选择；留空表示继承。每一级还可按能力指定不同模型。解析顺序与能力限制见 [Agent 实现说明](16-agent-implementation.md)。修改全局默认不会清空已经明确设置的局部覆盖。

## 活动节点

按用户最新要求移除 N01“明确副业目标”，当前活动目录为 **N02—N50，共 49 个节点**。保留编号是为了历史引用稳定，显示序号与 ID 不要求一致。N02 不再依赖 N01；G01 也不再审阅 N01。

服务端首次读取旧工作区时，在一笔事务中把 `nodes.N01` 及其绑定移到 `archivedNodes`、`archivedNodeBindings`，清除依赖引用并增加工作区版本。浏览器模式读取与操作时执行同样迁移。历史内容仍可从导出 JSON 查看。原有审批保留，但版本指纹改变后需要重新确认，防止悄悄沿用已变更的审阅范围。

## 流程导航

制作流程页默认是通用目录，不选择任何作品。点击节点展示输入与完成标准；在上方选择作品后，再打开该作品的节点。选择作品后点击其他节点直接进入该作品。作品编辑页可以返回带作品上下文的完整流程。节点搜索也进入通用目录，避免默认打开第一条示例。首页阶段入口携带阶段筛选条件。

作品与节点仍是不同层次：通用目录说明“应该做什么”，作品节点保存“这条视频做到了哪一步”。界面显式显示当前作品，不能把两者混为一谈。

## 删除任务

每条任务可删除，需要确认具体记录。命令 `DELETE_TASK` 只设置 `deletedAt`，默认列表隐藏，作品、产物与文件不受影响。在“已删除”中可用 `RESTORE_TASK` 恢复。不存在的 ID 被拒绝；所有写操作仍受版本并发保护。当前任务记录不存在运行中的后台模型作业，因此删除不代表取消远端作业。

## 文档版本

01—13 为最初设计，15 为首版历史验收，涉及“50 节点”的旧描述按本章更新；当前规范以 `specs/nodes.json` 和生成的 02 节点目录为准。14 记录首版边界，16 说明真实 Agent 状态。真实模型与外部执行器本轮仍未接入。

## 本轮验收

前端 12 项领域测试、6 项本地浏览器测试、3 项前后端联合浏览器测试、后端 6 项测试全部通过，共 27 项；TypeScript 与生产构建、可执行 JAR 打包、目录和文档检查通过。联合测试使用独立数据库与文件目录，不向正式工作区导入验收作品或素材。

新增检查覆盖全局/作品/节点继承与清除、不兼容能力回退、旧 N01 产物和绑定归档、迁移幂等与数据库版本、任务删除/取消/恢复、通用流程说明和不同作品跳转、Agent 状态说明。桌面与 390px 手机界面均有浏览器检查。

更新前停止本项目进程，备份数据库及旧程序到 `.run/backups/`，随后替换源码和执行包并重启。素材原件不修改。界面参考见 [更新后的流程页](screenshots/workflow-context.png)。

部署后复核：本机服务正常，原作品与任务数量保持一致；全部旧 N01 已归档，活动节点无 N01；迁移版本已保存。更新目录再次生产构建通过，小屏全局模型按钮与无横向溢出复核通过。
