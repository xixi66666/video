# 08 外部工具与异机接入流程

## 1. 当前边界

**已实现工作台到远程媒体 Worker 的 HTTP 客户端和持久生成任务，默认关闭；Worker 及 ComfyUI 等具体工具适配尚未部署实现。** 当前配置项指向本项目的 Worker 协议，不直接指向 ComfyUI。OBS、Remotion、FFmpeg、剪辑软件、平台发布与指标仍为 DOCUMENTED。登记 URL 不代表已经联通或完成生成。实际接口见 [视频制作与媒体 API](26-production-lottery-and-media-api.md)。

工具生命周期：DOCUMENTED → CONFIGURED → VERIFIED → ENABLED；验证失败保留诊断，停用为 DISABLED。声明能力与实测能力分开。配置示例见 `examples/comfyui-registration.example.json`。

## 2. 控制端与执行端

- 控制端：页面、业务后端、数据库、任务记录、确认、预算、素材目录与可选中央存储。
- 执行端：目标电脑上的 ComfyUI、模型、节点、GPU、媒体工具；后续需要时安装 Worker/Gateway。
- 两端通过受控网络和认证通信；原生工具没有满足需求的认证时，通过反向代理/网关补充。不把工具端口直接开放公网。
- 文件通过对象存储、受限 HTTP 上传下载或明确共享存储交换。不能把远端绝对路径当成本机路径。
- 内网地址或专用网络允许范围由管理员明确登记；既不能允许任意 URL，也不能一刀切阻止用户的合法远端执行机。

## 3. 统一执行合同（拟实现）

```text
describe() -> 声明能力、模板、资源和取消能力
validate(template_revision, bindings, input_manifest) -> 缺项与参数诊断
submit(job_spec) -> 外部任务标识/明确拒绝/受理未知
status(external_job_ref) -> 排队/运行/成功/失败/未知
collect(external_job_ref) -> 文件清单、校验信息与来源
cancel(external_job_ref) -> 已取消/不支持/取消请求中/未知
health() -> 心跳、环境版本、资源状态
```

job_spec 包含本地 task/attempt ID、幂等键、模板版本与哈希、参数绑定、输入文件清单、输出约定、授权、资源与费用边界。输出 manifest 包含每个文件的 media_type、大小、sha256、来源任务、镜头/音轨对应关系。

上面的方法是本系统内部接口，不声称每个外部工具原生都有这些端点。适配器必须报告不支持的能力，并提供手工降级。

## 4. ComfyUI 接入前准备（在目标机器实施）

1. 记录操作系统、GPU/显存、驱动、运行环境、ComfyUI 版本。
2. 确认目标模型、授权条件、节点依赖与工具版本，形成 environment manifest；不依据当前电脑猜硬件要求。
3. 在目标 ComfyUI 中手工跑通一个最小工作流和一条代表性镜头。
4. 保存可读工作流及 **API 可执行格式**；两者不能默认互换。界面导出位置以目标版本为准。
5. 保存模型、节点、输入输出格式和资源需求；固定一个验证通过的模板版本。
6. 给模板声明可填写参数，绑定真实 node_id、input_name 与输出节点，不使用网上示例中的固定节点编号。
7. 配置受保护的访问路径、认证和文件传输方式，验证控制端可访问。

接入前完成这七步，不代表操作台已经具备连接器代码；后续实现再按照下列流程联调。

## 5. 原生 ComfyUI 接口与系统映射

以下按官方自托管 Server Routes 文档核对，目标版本仍需验证。云托管和第三方代理接口不直接套用。

| 原生接口 | 拟用途 | 约束 |
| --- | --- | --- |
| GET /system_stats | 环境与资源探测 | 不据显存数据承诺某模型一定能运行 |
| GET /object_info | 获取可用节点定义 | 检查模板节点类型、参数和依赖 |
| POST /upload/image | 传入参考图 | 校验文件类型、大小、所有者与返回定位 |
| POST /prompt | 提交 API 工作流 | 保存返回 prompt_id；验证失败保存 node_errors |
| GET /queue | 检查队列 | 不自动清空其他人的任务 |
| GET /history/{prompt_id} | 任务历史与输出信息 | 只查询归属任务，保留本系统长期记录 |
| WS /ws | 执行状态与进度 | 断开后通过历史/队列对账，不把断线当失败 |
| GET /view | 获取输出文件 | 限制合法文件参数，获取后计算校验并入库 |
| POST /interrupt | 中断当前执行 | 不是通用的“按任务 ID 取消”；只在确认独占与任务归属时使用 |

官方来源：[Server Routes](https://docs.comfy.org/development/comfyui-server/comms_routes)。

原生提交的基本形状是：

```json
{
  "client_id": "controller-generated-client-id",
  "prompt": {
    "REAL_NODE_ID": {
      "class_type": "REAL_INSTALLED_NODE_CLASS",
      "inputs": {}
    }
  }
}
```

这是结构示意，**不是可执行工作流**。真实图中的连接、参数、节点和必需模型必须从已跑通模板获取，不能让 Agent 随意补齐后直接生产。

## 6. 一次镜头任务的接入时序

用户确认 G03 和制作预算 → 解析镜头需要的能力 → 选择已验证模板 → 校验输入和参数 → 冻结 workflow/input/model/node 版本 → 上传输入 → submit → 保存 prompt_id → 接收进度 → 历史对账 → 下载输出 → 文件校验 → 内容检查 → 候选素材归档 → 人工或既定规则采用。

本地任务 ID、attempt ID、prompt_id 与输出路径一一关联；服务端提交超时且是否受理未知时先对账。不支持外部幂等时记录风险，不能承诺端到端 exactly-once。

## 7. 模板与参数管理

- 正式生产只调用验证通过、不可变的模板 revision。
- 允许填写的参数有类型、范围、默认值和对应节点；工作流 JSON 本身与运行参数分开。
- Agent 可以建议新增工作流；先在测试环境跑样片，再发布模板，不在正常生产中随意安装节点或下载模型。
- 缓存可能减少重复计算，但不能把某次缓存行为当成所有任务都可复现的保证。
- 固定种子不等于跨硬件、模型和节点版本输出完全相同；保存复现条件而不是承诺逐像素复现。

## 8. 失败与取消

缺节点/缺模型/参数错误：配置失败，停止自动重试。OOM：记录资源需求，按已批准方案缩小或换执行端。网络中断：先查询任务。内容不合格：修改制作条件。运行时依赖升级：模板验证失效。

默认不能调用全局清队列或中断别人的任务。共享 ComfyUI 如无法证明任务归属，取消策略为等待完成并丢弃/保留候选，由用户决定；独占执行器可使用经验证的中断能力。

## 9. 其他工具的接入流程

| 工具 | 需登记/约定 | 当前无连接器时 |
| --- | --- | --- |
| OBS | 场景、采集源、音轨、输出、真实控制能力 | 导出拍摄清单，手工录制后上传 |
| 浏览器演示 | 目标环境、模拟数据、允许网址、动作、录制与结果证据 | 用户操作录屏；生成画面不能代替实测 |
| FFmpeg/ffprobe | 可执行版本、允许的处理模板、输入输出和限制 | 使用现有工具手工处理后导入 |
| Remotion | 模板/代码版本、参数 Schema、字体、渲染环境、使用许可 | 导出素材与说明，人工渲染导入 |
| 人工剪辑软件 | 版本、素材路径、工程/时间线交换能力、字体与色彩 | 交付素材包、字幕和剪辑要求，回传工程与成片 |
| TTS/ASR 等 API | 供应商协议、认证、模型能力、单位与限制 | 使用外部工具制作，标记人工来源 |
| 平台发布 | 账号身份、官方能力、草稿/定时/查询权限、费用 | 导出发布包，人工上传，导入链接和状态 |
| 评论与指标 | 数据权限、时间窗、字段口径、分页与频率 | 上传后台导出的数据或人工记录 |

任何第三方平台接入先核实官方能力、授权和使用限制；不承诺所有账号可自动发布、读评论或读取经营数据。浏览器自动化不是通用平台接口替代方案。

## 10. 未来联调验收

最小工作流、代表性镜头、真实模板绑定、进度和文件回收；超时受理未知、WebSocket 断线、缺节点、缺模型、OOM、取消归属；目标机重启后的对账；重复提交防护；文件搬运校验；停用工具后手工入口仍可完成节点。
