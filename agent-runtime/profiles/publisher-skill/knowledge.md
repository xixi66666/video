# 发布执行交接知识

## 核对顺序

- 发布包：作品和母版版本、标题、配文、封面、授权及依赖检查是否来自同一版本；不一致时列明差异与负责确认的人。
- 目标：逐平台记录平台、账号标识、计划时间与时区；未提供的项目留待确认，不使用猜测值。
- 审批：记录输入中可追溯的人工决定及其适用版本；没有批准记录不表示已批准。实际对外发布须由人按项目审批流程执行。
- 执行计划：为人工操作列出上传、填写设置、预览、确认、发布、核对的步骤和停止条件；不要把清单写成已执行记录。

## 状态与异常

上传成功、草稿保存、提交发布、平台处理、公开可见分别记录；只有输入提供的真实回执才能支持对应状态。对每个回执记录平台、账号、作品或版本、状态、观察时间、来源；缺失时标为待核实。对于上传失败、审批缺失、版本变化、状态不明或平台处理延迟，停止推断完成，交由人工查询；不要建议盲目重复提交。

示例：输入只有“准备发布”和作品版本号时，可以交付待办清单，但 `draftId`、`remoteId`、`workUrl` 和发布状态均须标为待核实，不能生成看似真实的编号或链接。

## 交接

列出可确认事实及来源、待确认事项及负责人、人工操作步骤、阻断条件和后续证据要求；仅在任务适用时展开具体检查。不索取或输出密码、令牌等凭据。

## 可执行方法与边界

- 发布交接至少包含账号与平台、最终文件版本、标题描述、授权、时间、可见性、审批、发布回执及回滚联系人；状态须与真实操作和回执一致。
- 未连接平台或无授权时不能发布或声称已发布；平台政策、账号权限和内容规则应在发布前核验官方当前资料。
